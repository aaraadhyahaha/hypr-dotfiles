# AGS Design System

## Layout

```
style.scss              index, only @use lines
colors.scss             GENERATED by matugen — edit ~/.config/matugen/templates/ags-colors.scss
styles/_tokens.scss     spacing, radii, type, motion, state layers, semantic colors
styles/_mixins.scss     flat-button, interactive, tile, on-state, panel, notif-text, track
styles/_base.scss       globals: transitions, .glyph, .sep, .pulse
styles/_<widget>.scss   one partial per widget (bar, popovers, notifications, media, quicksettings, pomodoro, desktop, …)
```

Each partial starts with:

```scss
@use "../colors" as *;
@use "tokens" as *;
@use "mixins" as *;
```

## Color roles (Material 3, from matugen)

| Use | Token |
|-----|-------|
| Bar background | `$bar-bg` (`rgba($surface, .55)`) |
| Popovers, cards, toasts, OSD | `$panel-bg` (`rgba($surface-container, .82)`) via `@include panel` |
| Tiles/rows inside a panel | `$card-bg` (`$surface-container-high`) |
| Slider / progress troughs | `$track-bg` (`$surface-container-highest`) |
| Primary text | `$text` (`$on-surface`) |
| Secondary text | `$text-muted` (`$on-surface-variant`) |
| Placeholder / disabled | `$text-faint` (`$outline`) |
| Separators, hairlines | `$outline-variant` |
| Accent (fills, active dots, progress) | `$primary` / `$on-primary` |
| List selection (launcher row, audio device) | `$secondary-container` / `$on-secondary-container` |
| Break / secondary accent (pomodoro) | `$tertiary` / `$on-tertiary` |
| Destructive | `$error` / `$on-error` |
| Urgent / critical (urgent workspace pip, critical notification edge) | `$error` |

Never hardcode a hex or `rgba(<number>…)` — both break when matugen switches to light mode.

## State layers

Interactive elements overlay `$on-surface` at fixed alphas:

| State | Token | Alpha |
|-------|-------|-------|
| hover | `$state-hover` | .08 |
| pressed | `$state-pressed` | .12 |
| selected | `$state-selected` | .16 |

`@include interactive($radius)` applies these to a transparent button. `@include tile($radius)` does the same on a `$card-bg` fill.

## On-state rule

Every toggle that is **on** — QS tiles, Wi-Fi/BT halves, the Dark/Light segment, Caffeine, the pomodoro play button — uses `@include on-state`: solid `$primary` background with `$on-primary` content. List selection is the exception: it uses `$secondary-container`, so it doesn't compete with the toggles.

## Spacing, radii, type

- Spacing: 4px grid, `$spacing-1` (4) … `$spacing-8` (40).
- Radii: `$radius-xs` 4, `-sm` 8 (bar items, menu items), `-md` 12 (bar body, rows), `-lg` 16 (panels, tiles), `-xl` 20, `-full` 999 (pills, dots, badges).
  Nested radius = outer radius − padding (a card with `-lg` and 8px padding gets `-sm` children).
- Type: `$font-size-base` 12 for secondary, `-lg` 13 for bar/UI, `-2xl` 15 for titles and entries.
- Icons: everything is 16px (`$icon-size`; `$glyph-size` aliases it). Glyphs use `$font-icon` (JetBrainsMono Nerd Font **Propo**): in the plain Nerd Font variant the glyph's ink is wider than its advance, which pushes icons off-centre in their highlight.

## Bar

Every bar item is `$bar-item-h` (24px) tall and shares `interactive($radius-sm)`.

- Icon-only buttons (launcher, caffeine, power, tray) are 24×24 squares with the icon centred.
- Text or composite buttons (bell, pomodoro, QS pill) use `padding: 0 $spacing-2`. Static items (clock, battery, window title) use the same padding with no hover.
- Gaps inside an item: `$spacing-1` between sibling icons (QS pill, tray) and `$spacing-2` between an icon and its text (battery, bell count, clock date).
- Clock and bell are one item (`DateMenu`): its popover holds grouped notifications and a calendar.
- The media pill (`widget/media`) sits after the date menu and only exists while an MPRIS player does.
- Workspaces: at least five pips, growing to the highest workspace in use; `.occupied`, `.active` and `.urgent` (pulsing `$error`) states, plus a ring for the scratchpad. Each button fills the bar height with `$spacing-1` side padding, and the 8px `.pip` inside is only the visual. This keeps the click target large.
- Separators are `$outline-variant` with an 8px side margin.

## Motion

One split, everywhere: **Hyprland owns opacity, AGS owns geometry.**

- Hyprland fades every AGS layer and popup (`fadeLayersIn/Out`, `fadePopupsIn/Out`, curve `glassIn`), so the blur behind a panel fades with its tint. An opacity fade drawn by AGS can't do that: with `ignore_alpha` the blur snaps on and off at the threshold, which is a flicker. Only `shot` (the region selector) keeps `no_anim`.
- AGS moves content with `<Motion>` (`widget/common/motion.ts`), a wrapper that transforms its children at paint time on the frame clock. There's no relayout and no CSS-animation start race; the first frame paints the start pose, it can be interrupted, and it honours GTK's animations setting.
- Surfaces leave by hiding at once (`win.visible = false`, popover popdown); the compositor fades the last frame out. There are no exit timers.
- Never animate the size of a popover or other surface: a popup or layer that resizes every frame jitters. Content inside an open panel takes its space at once and settles in (`ENTER.content`).
- Launcher, files and clipboard are pinned from the top (`surfaceTop()`), not centred, so the search field holds still while the results change height.

| SCSS | `MOTION` (TS) | Use |
|---|---|---|
| `$dur-fast` 110ms + `$ease` | `fast` | hover, press, colour |
| `$dur` 200ms + `$ease` | `base` | routine state, revealer widths, OSD bar tween |
| `$dur-enter` 380ms + `$ease-out` | `enter` | geometry settling in, workspace pip stretch |
| `$dur-exit` 180ms + `$ease-in` | `exit` | geometry leaving |
| — | `slide` 460ms | toasts arriving from the screen edge |
| — | `settle(from)` (`enter`) | a desktop widget gliding into its slot after a drop, reflow or gallery drag |

Curves: `$ease` is `cubic-bezier(.25,.1,.25,1)`, `$ease-out` is `(.16,1,.3,1)` (fast arrival, then a long quiet settle) and `$ease-in` is `(.4,0,1,1)`. `EASE.*` in TS uses the same curves. No springs, no bounce.

`ENTER` presets (call `motion.animate(preset)` *before* showing; `onShow(popover, motion, preset)` wires a popover):

- `card`: launcher, files, clipboard, wallpapers. Scale 0.96 → 1 about the centre.
- `popover`: every bar popover. 4px drop and 0.97 scale, pivot at the top.
- `rise`: OSD, 14px up.
- `zoom`: overview, 1.04 → 1 (zooming out from the desktop). It captures *before* mapping, so it never opens invisible.
- `edge`: toasts and the screenshot preview slide in from past the screen edge. There's no fade, so the blur travels with the glass. `LEAVE.edge` slides them back out, then the slot's revealer collapses so the toasts below glide up.
- `content` / `side`: content appearing inside an already-open panel (Wi-Fi/BT lists, the clock's date). These fade themselves, because no compositor fade applies there.
- `add` / `LEAVE.remove`: a desktop widget appearing on the grid (0.9 → 1, fading) or removed where it stands. Like `content`, they fade themselves.
- `LIFT` (1.03): the scale of a desktop widget while it's being dragged.

`Pose` also has `sx`/`sy` (stretch one axis on top of `scale`), and `<Motion origin="top-left">` pivots on the corner. The desktop's resize morph uses both: the widget is rebuilt once at its new size, starts stretched back to its old box, and settles. It never resizes every frame.

Window titles cross-fade with no travel, so text never shimmers. Never hard-code a duration: use a token in SCSS and `MOTION.*`/`ENTER.*` in TS.

## Fields

Text entries use `@include field`: a translucent `rgba($surface, .5)` fill, so the layer blur shows through. It never uses `$card-bg`.

## Desktop widgets

`widget/desktop/`. One full-screen layer (`namespace="desktop"`) inside the bar's exclusive zone holds every widget on a grid. The window sits on BOTTOM, under the windows. Edit mode (Super+G, or right-click the desktop → Edit Widgets) moves it to TOP behind a scrim, which Hyprland blurs, and opens the gallery. The scrim is `$edit-scrim`, and the bar's window takes it too (`window.Bar.editing`): the desktop layer starts below the bar's exclusive zone, so without that the strip around the floating bar stays crisp and bright, leaving a hard line across the top.

| File | Role |
|---|---|
| `layout.ts` | Pure grid model: sizes, snapping, `nearestFree`, `reflow`, saved-layout format (tested) |
| `catalog.ts` | Pure list of kinds: name, category, sizes, default config (tested) |
| `registry.ts` | kind → render function and "Edit Widget…" editor |
| `store.ts` | The layout in `~/.local/state/ags/desktop.json`: debounced atomic saves; a corrupt file is kept as `.bak` and replaced by the default layout |
| `Desktop.tsx` | The window, the `Gtk.Fixed`, the ghost slot, the desktop menu, edit mode, drag-out-of-gallery |
| `Frame.tsx` | One widget: card, drag, resize handle, menu, remove badge |
| `Gallery.tsx` | The bottom sheet: categories, search, live miniatures |
| `widgets/*` | The widgets; `draw.ts` (cairo, `tween`, `tickWhile`) and `common.ts` (`Ring`, `Meter`, `Bars`) are shared |

- **Grid:** 72px cells, 12px gaps and a 24px margin. Sizes are S 2×2, M 4×2, L 4×4 and XL 8×4. A drop onto another widget moves the dragged one to the nearest free spot; ties go to the upper, then the left spot. The other widgets never move. The layout is saved with the grid it was arranged on; on another monitor scale (a different grid) `adapt` moves touching widgets as one group and shows each group flush against the edges it touched, else at the same distance from its nearer edge (or the same relative place in the middle third), without overwriting the saved layout until the next edit.
- **Dragging never relayouts:** the card follows the pointer as a `<Motion>` paint offset, and is moved in the `Gtk.Fixed` once, on drop, settling from its offset. The resize handle snaps to the kind's sizes, with a ghost that names the size.
- **Card:** `$panel-bg` glass, `$radius-xl`, 12px padding. Each frame has 10px of transparent bleed so the edit-mode badge straddles the card's corner. Rings, meters and bars are `$primary` (`$tertiary` for vision widgets, `$error` past a threshold) and ease in with `tween`.
- **Idle cost:** ticking (the clock's sweep) and polling (System) run only while `live` is true, meaning in edit mode or when no tiled or fullscreen window covers the workspace. fx refreshes on changes to `fx.db`, plus once a minute.
- **Data:** fx widgets read `fx status --json` (`service/fx.ts`); they never write to fx's database.
- **Gotchas:**
  - Put `visible` last on a layer window. Set before `layer`, the surface maps on Astal's default layer (TOP) first.
  - Hidden buttons must not be focusable. An invisible remove badge that has focus will take a stray Space.
  - Never run two `ags run` at once: they share `/run/user/$UID/ags.js`.
  - Map order doesn't decide which of two OVERLAY layers is on top (a surface GTK already created keeps its place). Use Hyprland's `order` layer rule, where a *lower* order is nearer the top: `shotmenu` has `order = -1` so the screenshot toolbar stays above `shot`.
  - A layer with keymode EXCLUSIVE takes the pointer from every other layer, whatever their order. A full-screen overlay that sits under another clickable layer (`shot`) uses ON_DEMAND, which still takes focus when it maps.
