# AGS Shell (~/.config/ags)

Desktop shell for Hyprland: bar, control center, launcher, OSD, notifications, desktop widgets.

## Stack
- AGS v3 + gnim, GTK4, TypeScript/TSX (`jsxImportSource: ags/gtk4`), SCSS
- Prettier: no semicolons, 2-space indent

## Commands
- Run: `ags run` (never two at once: they share `/run/user/$UID/ags.js`)
- Test all: `npm test` (Node's test runner over `widget/**/*.test.ts`, `service/**/*.test.ts`)
- Test one: `node --test service/fxModel.test.ts`

## Finding code — don't explore, look it up
- `FEATURE_MAP.md` maps feature IDs (e.g. `cc.wifi`, `bar.pomodoro`) to exact files and line ranges.
  It's large: read only its index (`## 0. Index`) or grep for the one section you need, then open just those files.
- `DESIGN.md` holds visual rules (tokens, motion, on-state, gotchas). Grep the relevant heading; don't read it whole.
- `@girs/` and `node_modules/` are generated type stubs: never read or search them.

## Layout
- `app.ts` — startup, IPC request handler, window list
- `widget/<feature>/` — one folder per UI feature; `widget/common/` has Icon, motion, surface
- `service/` — system, recorder, pomodoro, fx data (`*Model.ts` = pure logic with a `*.test.ts`)
- `styles/_<widget>.scss` — one partial per widget; `style.scss` is only `@use` lines
- `colors.scss` is GENERATED by matugen — never edit it

## Rules
- Pure logic lives in a `*Model.ts` next to its widget/service; change it → run its test.
- Never hardcode hex or `rgba(<number>…)`; use tokens. Never hardcode durations; use `MOTION.*`/`ENTER.*`.
- fx widgets only read `fx status --json`; never write to fx's database.
- Delegate test runs, log reading and doc lookups to the `runner` subagent.
- Small changes, test after each.

# Compact instructions
When compacting, keep: the current plan, FEATURE_MAP IDs involved, files changed, open test
failures and decisions made. Drop: exploration, file dumps, passing test output.
